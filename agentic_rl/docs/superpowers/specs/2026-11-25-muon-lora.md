# Muon 独立训练预设

当前候选使用 Qwen3-4B-Instruct-2507、LoRA rank 32、alpha 64、单卡 FSDP 和 GRPO。以同一 SFT 权重、同一奖励配置开始独立实验。AdamW 是默认优化器，显式选择 `--optimizer muon` 才切换。正式虚拟环境 PyTorch 2.11.0+cu129 已包含原生 Muon。

| 参数 | 首轮取值 | 选择依据 |
| --- | --- | --- |
| 学习率、调度、权重衰减 | `1e-5`、恒定、`0.01` | 学习率按 LoRA GRPO 独立选取，作为 Tau2 上的首跑值 |
| 更新尺度 | `match_rms_adamw` | 按矩阵形状调整，适用于 A、B 两种方向的矩形因子 |
| 动量、Nesterov | `0.95`、开启 | 作者实现与 PyTorch 的起始设置 |
| Newton–Schulz | 5 次，系数 `(3.4445, -4.775, 2.0315)`，`eps=1e-7` | 使用 PyTorch 2.11 原生算法的默认数值设置 |
| 梯度裁剪 | `1.0` | 沿用当前 GRPO 配置 |

NVIDIA NeMo Helix 把 `1e-5` 列为 LoRA GRPO 通用默认值。在更接近多轮代理的 ALFWorld 研究中，作者用 Muon `3e-5` 训练 GRPO，但采用 Qwen2.5-0.5B、完整隐藏层矩阵及非零 KL 损失，且 GRPO 只测了一个 Muon 学习率。针对这里的 Qwen3-4B、rank 32、24K 上下文和关闭 KL 的设置，我选择较低的 `1e-5` 起跑。这是工程判断，Tau2 上的效果尚待实测。[NVIDIA 官方 GRPO 配置](https://docs.nvidia.com/nemo-helix/latest/documentation/customizer-reference/manage-customization-jobs/training-configuration) · [ALFWorld 研究附录 A](https://arxiv.org/html/2607.16169v1)

作者实现采用五次正交化迭代，PyTorch 2.11 提供对应参数及 `match_rms_adamw`。这里分别对训练中的二维 LoRA A、B 做 Muon 更新，基座冻结。[作者实现](https://github.com/KellerJordan/Muon/blob/master/muon.py) · [PyTorch 2.11](https://docs.pytorch.org/docs/2.11/generated/torch.optim.Muon.html)

在 Qwen3-1.7B/4B 的数学 RLVR 实验中，也有作者报告原版 Muon 训练退化。不同任务、更新参数和矩阵缩放方式都会影响学习率的可迁移性。[Qwen3 RLVR 研究](https://arxiv.org/html/2605.19282v1)

这里的 `match_rms_adamw` 只指定矩阵更新的缩放公式。Muon 的基础学习率独立设置。启动时按 FSDP 元数据核验每个可训练参数仅含一块完整的二维 FP32 LoRA 权重。构建优化器和执行更新时，将共享同一存储的权重、梯度按各自原始行列数交给 Muon。采样和保存继续使用正式实验的 FSDP 布局。恢复时绑定优化器配置和参数布局。

## 使用方式

把候选代码同步到训练环境后，在 `agentic_rl` 目录、原有 RL 虚拟环境及环境变量下，先为固定版本的 veRL 安装可选补丁，再核对训练命令。

```bash
python scripts/apply_verl_lora_precision.py --muon "$VERL_ROOT"
python scripts/train_airline_grpo.py --stage full_train \
  --config configs/rl/airline_procredit_v4_train30_c32_routed.yaml \
  --optimizer muon --dry-run
```

正式实验沿用已定的步数、采样和评测设置，从相同的合并 SFT 权重开一条独立运行。对应启动命令去掉 `--dry-run`。默认生成的运行名带 `_muon`，启动记录保存实际超参数。

需要手动指定其他 Muon 学习率时，可在同一命令中附加 `--extra actor_rollout_ref.actor.optim.lr=2.0e-05`。在优化器选择后应用此值，并写入训练记录及恢复校验。

## 已验证范围

正式虚拟环境的 CPU 验证使用固定版本 veRL、原生 PyTorch 2.11、单进程 FSDP 和 rank 32 的小型 LoRA 网络。已核对优化器参数组实际收到 `lr=1e-5`。两块权重分别为 32×96、64×32，前向 BF16，梯度、主权重和动量为 FP32。中间保存再恢复后，下一步权重与动量逐元素等于连续运行。冻结基座通过一致性检查。

另用随机初始化的单层小 Qwen3，在 `1e-5` 下走 veRL 的 PEFT 注入、FSDP 自动包装和 BF16 autocast。两步后 7 个线性投影的 14 块 A/B 矩阵全部有更新，所有冻结权重逐元素与初始值一致。

验证时，`use_orig_params=true` 在包含冻结层的嵌套 FSDP 测例中触发了权重导出异常。最终采用基线的 `use_orig_params=false`，并验证了旧补丁升级、全新安装和恢复。完整 4B 模型的 GPU 吞吐、显存与任务成功率需要正式实验测量。
