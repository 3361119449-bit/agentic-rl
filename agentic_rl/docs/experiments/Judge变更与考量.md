# Judge 变更与考量

## 2026-11-25 · 纯查询退出逐轮 Judge

本地训练候选配置启用 `judge.exclude_pure_queries`。下列六种工具在单独调用、成功执行且未夹带客服话术时，跳过该助手轮的 Judge 判定。

- 资料查询：`get_user_details`、`get_reservation_details`、`get_flight_status`、`list_all_airports`。
- 航班搜索：`search_direct_flight`、`search_onestop_flight`。

调用及回执继续保存在整轨请求中，后续轮可以引用已经可见的结果。`calculate`、写操作、客服回复、失败或混合调用继续进入原有评分流程。确定性重复查询检测照常参与训练标签合并。

### 训练信号的考量（原文）

**对训练信号最直接的改变在 Task 11。** A7、A8 搜错航线，这两步会失去 Judge 给的 `bad` 标签；A10 拿错误航线报退款金额、A12 把实际退款金额说错，这两步仍然要评。重复搜索也继续由程序检查。换句话说，你接受了**搜偏但及时纠正可以不罚，搜偏后真的报错价则罚在报价轮**。

### 离线回放

采用上次 30 个任务各一条的冻结轨迹，复用保留轮的历史判定。410 个助手轮中，211 个纯查询退出逐轮 Judge，余下 199 轮仍需判定。合并程序检查后，只有 Task 11 的 A7、A8 从 `bad` 变为无坏轮标签。A9 的错误计算、A10 的错误报价、A12 的错误实退金额保留坏轮标签。跳过 Judge 的 211 轮中，15 轮仍由确定性检查判为坏轮，其中包括 Task 42 A7 的重复订单查询。
