# Reward v11

默认配置为 configs/rl/airline_procredit_v4.yaml，奖励标识
v11-procredit-transfer-query-req。此前默认配置保存在
configs/rl/airline_procredit_v4_v10.yaml。ProCredit-v4、simple-turn-v1
最终优势规则和 simple-turn-target-v2 因果裁判保持原计算框架。

## 三项修改

1. transfer-policy-v2：allowed 只作参考。结合 required、forbidden、
   绑定政策、实际用户诉求与工具结果，由 Judge 明确给出合法性、动态必要性、
   是否仅因助手自身错误等结论。不完整结论在缓存前拒收并有界重试。
   合法转接消除对应误罚，不自动算完成。只有原有 required 任务保留转接完成目标；
   非法或仅由助手错误造成的转接不能产生该完成信用。真实错误取消后的恢复转接，
   可以合法且 self_caused_only=true，原错误继续处罚。
   没有执行工具的口头转接，只有明确归因的失败政策检查可标为适用，不能算执行成功。
   用户禁止转接、普通政策拒绝、助手臆造的能力缺失均不能自动变成强制转接理由。

2. duplicate-query-v1：保存每次工具参数、结果、全库前后 hash，以及原生相关状态
   的作用范围和前后指纹。成功的只读查询与此前成功查询同名、同标准化 JSON 参数、
   同相关状态时，第二次及以后进入 bad_turn。失败后的重试、写操作、控制操作、
   未执行的本地拒绝调用不计。相关状态变化允许复查；无关写入和不可组成完整连接的
   航班变化不豁免重复。用户要求原样重查且状态未变仍处罚。
   不增权重，最终优势仍执行 min(A0,-1)，同一回合只约束一次。
   缺少原生证据时明确失败，不能假设状态未变；旧轨迹先按固定初始 DB 原生重放。

3. progress-v3：DB、COMM、REQ 一起计入，不再因有 DB 屏蔽必要操作。
   保留原有 required 转接子目标，并加入必要操作。每项成功且参数匹配的 REQ
   只计一次；写操作要求实际 DB 效果。初始满足项排除，Phi0=0，
   Phi 为已满足项/纳入项，范围0到1，progress_scale=0.5。
   因而这一进度分量上限仍为0.5，已有截断乘数保持不变。
   progress-v1/v2 保留以复现历史条件。

## 保留与复现

正确拒绝首次 +1、最终优势至少+1，仍按请求去重并检查撤销。
错误优先，坏轮最终优势至多-1。原有终局评分、过程成本、组内计算、
token/observation mask、优化器、BF16、采样参数、Target-v2 请求语义保持不变。
没有新增确认范围、多工具、局部质量 Judge 或轨迹级 policy hard gate。

离线验收使用冻结80条 SFT-v4 C8 轨迹、1227个助手轮次；不重新 rollout。
离线审计为20组、每组4条；在线训练仍每组8条。
原始消息、工具结果、token、官方奖励保持原样。
确定性证据、进度、坏轮合并和优势重新计算。
沿用 Target-v2 结果须逐条核验原因果请求、返回、缓存哈希。
组合 Judge 结果必须明确保存实际原请求和每次替换来源，不冒称新的缓存命中或整条
原始 API 返回。缺少 DB 证据不能通过 Judge 重试补造。

新版本使用新实验身份，不能冒充旧奖励实验的精确续训。
CPU、原生工具重放及离线回归不等于已完成 GPU RL smoke test。
